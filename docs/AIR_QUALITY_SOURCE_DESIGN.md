# 대기질 소스 전환 설계 — 에어코리아 실측(한국) + OpenWeather 폴백

> 상태: **설계만 — 오너 승인 대기, 구현 착수 금지.** 2026-07-31.
> 발단: 실측 3자 대조(광화문 동지점 동시각) — 우리 파이프는 OpenWeather에
> 충실(소수점 일치·환경부 breakpoint 일치·캐시 신선 — 전 구간 무죄)하나,
> OpenWeather 대기질은 **글로벌 모델값**이라 측정소 실측과 5배 괴리
> (실측 PM10 21/PM2.5 19 vs 모델 119/102). 이 값이 러닝 지수(0/100
> "무리하지 마세요")까지 오염 — 러닝 앱 핵심 판단 입력이 틀린 상태.
> 부속: UV가 daily max 시맨틱이라 밤 20:53에 "매우높음 9.3" 노출(실측).

## 0. 요약

- **한국(입력 bbox) = 에어코리아 측정소 실측 / 해외·장애·결측 = OpenWeather
  폴백** — "한국은 한국 소스"(T-map/Kakao) 패턴 그대로.
- 측정소 선정: **Kakao transcoord(WGS84→TM, 기존 키 재사용) → 근접 측정소
  목록 API** — 신규 외부 의존 0개(에어코리아 키 1개만 추가).
- grade는 **에어코리아 khaiGrade를 쓰지 않고 µg 실값 + 기존 breakpoint 표
  재사용**(환경부 기준 동일·검증 완료 — 매핑 로직 단일 소스 유지).
- UV 추천: **ⓐ 야간(일몰~일출) value 0·"낮음" + 주간 현행 유지** — 기존
  주야 판정 코드(weather_service.py:427-436) 재사용, 추가 콜 0.
- 응답 스키마·grade 어휘·에러 계약 **불변**. 플래그 `AIRKOREA_ENABLED`
  기본 OFF = 현행 복원이 롤백 경로.

## 1. 에어코리아 API 조사

### 1.1 서비스 구성 (공공데이터포털 data.go.kr, 한국환경공단)

| 용도 | 서비스/오퍼레이션 | 입력 | 출력 |
|---|---|---|---|
| 근접 측정소 | `MsrstnInfoInqireSvc/getNearbyMsrstnList` | **TM 좌표**(tmX, tmY) | 거리순 측정소 목록(stationName, tm 거리) |
| 실시간 측정값 | `ArpltnInforInqireSvc/getMsrstnAcctoRltmMesureDnsty` | stationName, dataTerm=DAILY, ver=1.3+(pm25 포함) | pm10Value·pm25Value(µg 문자열)·pm10Grade·pm25Grade·khaiGrade·dataTime·*Flag |

- **TM 좌표 변환**: 에어코리아 근접 측정소 조회가 TM(중부원점) 입력을 요구.
  **Kakao `/v2/local/geo/transcoord.json`(WGS84→TM)** 사용 — 이미 보유한
  KAKAO_REST_API_KEY 재사용, 신규 키·의존 없음. (에어코리아 자체
  `getTMStdrCrdnt`는 읍면동명 입력이라 좌표 기반 흐름에 부적합.)
- **갱신 주기**: 측정소는 **매시 정시 측정, 10~20분 후 공개**(1시간 주기) —
  10분 TTL 캐시보다 느린 소스라 캐시 부담 없음. `dataTime`으로 관측 시각 확인.
- **응답 값 형태**: pm10Value·pm25Value는 µg/m³ **실값(문자열)** — 기존
  `_PM25_BOUNDS(15/35/75)`·`_PM10_BOUNDS(30/80/150)`(weather_service.py:81-82,
  환경부 기준 수치 일치 검증 완료)를 **그대로 재사용 가능**. khaiGrade 등
  자체 등급 필드는 무시(§8 결정 이력 — 매핑 단일 소스).
- **결측 실재**: 값 자리에 `"-"` 또는 `-999` + `pm10Flag`/`pm25Flag`에
  "점검및교정"/"장비점검"/"통신장애" 류 문자열 — **결측 코드는 실재하며
  파싱 시 float 변환 실패·플래그 존재를 결측으로 판정**(§2 폴백 트리거).
  정확한 결측 표기는 키 발급 후 실프로브 1회로 fixture 채집(§6 테스트).

### 1.2 오너 콘솔 작업 (키 발급 — 5단계)

1. https://www.data.go.kr 회원가입/로그인.
2. 검색창에 **"한국환경공단_에어코리아_대기오염정보"** → 상세 페이지 →
   **[활용신청]** 클릭(개발계정 — 자동승인, 활용목적은 "앱 서비스" 간단 기입).
3. 같은 방식으로 **"한국환경공단_에어코리아_측정소정보"** 도 활용신청
   (근접 측정소 조회가 별도 서비스라 **2건 모두** 필요).
4. 마이페이지 → 활용신청 목록 → **일반 인증키(Encoding) 복사**
   (두 서비스는 같은 계정 키 공유 — 1개 키로 둘 다 호출).
   ⚠️ 발급 직후엔 401이 뜰 수 있음 — **활성화까지 ~1시간 대기가 정상**.
5. 키를 Claude Code에 전달하지 말고 **fly secrets로 직접 설정**(배포 단계):
   `fly secrets set AIRKOREA_API_KEY=<키> --app freshrun-api`
   (로컬 .env에도 같은 키명 추가 — 값은 채팅에 노출 금지).
- **쿼터**: 개발계정 기본 일일 트래픽(콘솔 활용신청 페이지에 명시 — 통상
  500~1,000/일, **정확값은 2번 단계 화면에서 확인해 회신**). 초과 필요 시
  운영계정 전환 신청. 예상 사용량: 캐시 설계(§4)상 **일 수백 콜 이내**
  (그리드당 10분 1콜 + 측정소 매핑 일 1콜)라 개발계정으로 베타 충분.

## 2. 폴백 체인

```
lat/lng ── 한국 bbox(33~39, 124~132 — KoreaCoordinate와 동일 상수) 안?
  ├─ 아니오 → OpenWeather (현행 그대로)
  └─ 예 → 에어코리아:
       transcoord(캐시) → 근접 측정소(캐시) → 실시간 측정값
       ├─ 성공 + pm10/pm25 중 1개 이상 유효 → 채택 (부분 결측은 있는 값만)
       └─ 실패(HTTP/timeout/파싱) 또는 전항 결측(-·-999·Flag) → OpenWeather 폴백
```

- 폴백은 **요청 단위 best-effort** — 에어코리아 장애가 날씨 응답 전체를
  막지 않는다(현행 air 실패 시 무값 응답과 동형, §D best-effort 원칙).
- **소스 구분 클라 비노출(추천·§8)**: 응답 필드·grade 어휘 불변이 Ivan
  계약(와이어 값 고정)과 정합. 서버 관측용으로만 로그에 소스 기록.
  노출이 필요해지면 후일 additive 필드(`pm_source`)로 — 지금은 아님.

## 3. UV 시맨틱 3안 비교

| 안 | 내용 | 계약 영향 | 비용/콜 |
|---|---|---|---|
| **ⓐ (추천)** | **일몰~일출엔 value 0·grade "낮음", 주간은 현행(오늘 최고) 유지** | 필드·어휘 집합 불변(값만 밤에 0 — grade 어휘는 기존 "낮음" 재사용). 클라 무변경으로 체감 해소 | **0콜** — 주야 판정 코드 기존 재사용(weather_service.py:427-436, icon d/n + sys.sunrise/sunset 폴백) |
| ⓑ 현재 UV 소스 전환 | One Call 3.0(구독 필요·유료) 또는 Open-Meteo(무키 무료, current uv_index) | 값 시맨틱이 "현재"로 바뀜 — 어휘·필드는 불변이나 한낮 최대 경고가 사라져 안전 측 보수성 하락 | 신규 의존 1개(Open-Meteo) 또는 구독비 |
| ⓒ 현행 유지+라벨만 | 서버 무변경, 클라가 "오늘 최고" 라벨 표기 | 서버 0, **Ivan 클라 작업 필요** — 밤 "매우높음 9.3" 숫자는 계속 노출(체감 미해소) | 0콜 |

**추천 ⓐ 근거**: 러닝 앱의 질문은 "지금 뛰어도 되나"다 — 밤엔 자외선 0이
사실이고, 주간 daily max 유지는 한낮 최대 경고라는 보수적 안전성을 지킨다.
0콜·서버 단독 완결(Ivan 작업 0)·계약 불변. ⓑ Open-Meteo는 ⓐ 배포 후에도
체감 불일치 제보가 남으면 재검토(§8 트리거).

## 4. 캐시·계약

- **응답 캐시(기존)**: 10분 TTL·2자리 그리드 `_cache` 그대로 — 소스가 무엇이든
  조립 완료된 WeatherResponse를 적재(현행과 동일). lang 텍스트는 응답 시점
  조립(§C 함정 — 캐시는 ko 원데이터 공용) 규칙 무접촉.
- **측정소 매핑 캐시(신규, 서버 메모리)**: `그리드(2자리) → stationName`을
  **24h TTL** 별도 dict — 측정소는 사실상 불변이라 transcoord+근접 조회
  2콜을 그리드당 일 1회로 축소. 실측값 조회만 10분 캐시 주기로 발생.
- **응답 스키마 불변**: pm10/pm25 `{value, grade}` 그대로 — value가 실측
  µg로 바뀔 뿐. grade 어휘(좋음/보통/나쁨/매우나쁨) 불변 — **와이어 값 고정
  (Ivan 계약, 번역 금지) 준수**. 에러 계약 불변(weather 3종 503 그대로).

## 5. 러닝 지수 정합

지수는 `_running_index(..., pm25, pm10, ...)`(weather_service.py:194-205)가
`get_weather` 조립부에서 받은 **동일 pm 변수**로 `_dust_deduction`(:156-171)을
계산한다 — 소스 교체 지점이 pm 변수 대입부 한 곳이므로 **지수는 자동으로 새
실측값을 받는다**(별도 수정 0). 확인 지점: get_weather의 air 파싱→pm25/pm10
변수→ⓐ배너 필드 ⓑ_running_index 인자 — 두 소비처가 같은 변수를 읽는지
구현 시 assert(테스트 §6-4: 실측 21/19 주입 시 지수 감점이 "좋음" 구간).

## 6. 롤아웃·테스트 계획

- 설정: `airkorea_enabled: bool = False` + `airkorea_api_key: str = ""`
  (config.py — ANCHOR_POOL_N/SPUR_RESCUE 전례). OFF = 현행 100% 복원(롤백 1차).
- 순서: 구현+테스트 → **오너 키 발급(§1.2, 병행 가능)** → 플래그 OFF 배포 →
  스모크(현행 동작 불변) → `fly secrets set AIRKOREA_ENABLED=true` → 대조
  스모크(서울 1좌표: 배너값 vs 에어코리아 웹 공표값 근사 확인 + 해외 1좌표:
  OpenWeather 경로 불변) → 24h 관측.
- 테스트(실호출 최소화):
  1. **fixture 파서**: 정상 응답 / 결측 `"-"`·`-999`·Flag / 빈 목록 —
     키 발급 후 실프로브 1회로 채집한 실물 fixture(결측은 합성 보강).
  2. **bbox 분기**: 한국 좌표→에어코리아 경로, 해외 좌표→OpenWeather 직행,
     경계값(33.0/38.99) — 전부 mock.
  3. **폴백 주입**: 에어코리아 timeout/500/전항 결측 → OpenWeather 값으로
     응답 성립 + 응답 스키마 불변 assert.
  4. **지수 정합**: 실측 21/19 주입 → 먼지 감점 0(좋음), 모델 119/102 주입
     → 기존과 동일 감점 — 같은 변수 경로 증명.
  5. **UV ⓐ**: 야간 mock(icon 'n') → value 0·"낮음", 주간 → 현행값 유지.
  6. 실호출 스모크는 배포 단계 2회(한국 1·해외 1)만.

## 7. 미해결 쟁점 (오너 결정 필요)

1. **키 발급**(§1.2 5단계) — 이것 없이는 구현해도 스테이징 검증 불가.
   쿼터 실값도 콘솔에서만 확인 가능.
2. **UV 3안 택1** — 추천 ⓐ.
3. **소스 구분 노출 여부** — 추천 비노출(계약 불변).
4. **dataTime 스테일 표시** — 에어코리아는 1시간 주기라 최대 ~80분 전
  관측일 수 있음. 표시 추가는 additive 가능하나 추천은 미표시(클라 무변경,
  스테일이어도 모델 5배 괴리보다 정확).

## 8. 결정 이력 (§F — 결정 · 근거 · 재검토 트리거)

- **한국 PM = 에어코리아 실측** · 근거: 동지점 동시각 5배 괴리 실측 + 러닝
  지수 오염 · 재검토: 에어코리아 장애율이 관측상 유의미하면 이중화 검토.
- **khaiGrade 무시, µg+기존 breakpoint 재사용** · 근거: 매핑 단일 소스(§B),
  기존 표가 환경부 기준과 수치 일치 검증 완료 · 재검토: 환경부 기준 개정 시.
- **측정소 선정 = Kakao transcoord+근접 목록** · 근거: 신규 의존 0, TM 변환
  자체 구현 회피(오버엔지니어링 경계) · 재검토: transcoord 정확도 문제 시
  에어코리아 getTMStdrCrdnt 병행.
- **UV ⓐ(야간 0)** · 근거: 0콜·계약 불변·러닝 목적 정합·주간 보수성 유지
  · 재검토: ⓐ 배포 후에도 주간 체감 불일치 제보 시 Open-Meteo 현재값 전환.
- **소스 비노출** · 근거: 와이어 계약 불변·Ivan 작업 0 · 재검토: 유저 제보로
  "출처" 문의가 반복되면 additive `pm_source`.
