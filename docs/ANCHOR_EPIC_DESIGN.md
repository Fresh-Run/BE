## 0. 왜 이 에픽인가 (문제 종결 요약)

현행 v87은 **Gemini가 좌표를 발명 → 9-풀 → T-map 스냅 → 밴드 선택**. 세 부검이
"선택·프롬프트 층으로는 못 고친다"를 실험적으로 종결:

| 부검 | 결론 | 근거 |
|---|---|---|
| §8.13 | **선택 층 retrace 레버 무력** | 풀에 원형 후보 자체가 없음(min retrace 33~56), park 우선에 밀림 |
| §8.14 | **접근 제한 구역 지목**(용산 반환부지) | 좌표 발명은 지도 맥락 없음(B1) — 제한구역 경계 무지 |
| §8.15 | **프롬프트 비제어** | 원복 A·완화 H·anti-spur H2 전부 retrace 악화(71.5·74.5 > B 59) |

**공통 근본**: Gemini가 지도 없이 좌표를 발명 → 왕복·제한구역·무명 지점이 **원리적으로**
발생. **앵커 에픽 = 좌표 발명 원천 제거**: 서버가 지도에서 실재 runnable 앵커를 모아
주고, Gemini는 그 안에서 **테마·순서만** 고르고, 서버가 **원형 기하를 계산**. 원형성은
Gemini 설득이 아니라 **서버의 각도 분산 제어로 구조적 보장**(§3).

## 1. 앵커 검색 층

**목표**: 시작점 반경 내 **실재하는 runnable 앵커**를 수집·랭킹. 좌표는 지도 제공자
것만 사용(발명 0).

### 1.1 수집 소스 (병렬 Kakao)
- **공원·녹지**: keyword `공원`·`근린공원`·`호수공원` (sort=accuracy). AT4(관광명소)
  포함. **기존 `rank_places_for_keyword` 대표성 랭킹 그대로 재사용**(적합도·위치밴드·
  accuracy 순위 — 청라호수공원을 밴드 내 #1로 올린 실검증).
- **수변/트레일 시드**: keyword `한강공원`·`천`(하천)·`산책로`·`둘레길`·`강변` — 러닝
  선호 지형(현 프롬프트 STRONG "riversides, parks, waterfront"의 실체화).
- **랜드마크**: 시작 인근 대표 지점(광장·역·다리 초입) — 루프 꼭짓점 후보.

### 1.2 앵커 레코드
```
Anchor = { id, name, coord(lat,lng), type(park|water|trail|landmark),
           dist_from_start_m, rep_rank(accuracy 순위), sector(시작 기준 방위각 8분할),
           dead_end(bool), in_band(bool) }
```
- `in_band`: 시작 거리 ∈ [200m, target×0.5×1000] — **기존 위치 밴드 상수 재사용**
  (`_POS_BAND_LO_M=200`, `_POS_BAND_HI_FACTOR=0.50`). 밴드 내 = "루프 중간 자연 지점".
- `sector`: 시작 기준 방위각을 8분할 — **§3 각도 분산의 입력**(핵심).

### 1.3 dead-end 앵커 처리 (§8.14 "through-path 우선")
**문제**: 청라호수공원(교량 건너)·잠원 수변 스퍼처럼 **보행 경로가 왕복밖에 없는**
앵커는 루프 꼭짓점으로 쓰면 **강제 스퍼**(부검 2례 max_gap 331m 동일 교량).
- **판정(제안)**: 앵커를 T-map으로 **양방향 프로브**(시작→앵커, 앵커→다음 후보) —
  진입·이탈 leg이 **동일 세그먼트 재사용**(retrace)이면 `dead_end=true`. 저비용 대안:
  Kakao 주소에 수변/섬/지구 신호 + 단일 접근로 휴리스틱.
- **정책**: `dead_end` 앵커는 **루프 꼭짓점에서 제외**, **선택적 pitstop으로만** 허용
  (사용자가 "그 호수 찍고 오고 싶다"면 스퍼 감수 — pitstop은 원래 목적지). 루프의
  원형성은 through-path 앵커들이 담보.

### 1.4 캐시 (비용 방어 — §5)
앵커는 **정적**(공원 위치는 안 바뀜) → **격자 셀 키 캐시**(시작 좌표 반올림 + target
버킷, TTL 수일). 첫 요청만 Kakao 다콜, 이후 캐시 히트 → 콜 급감.

## 2. Gemini 역할 축소 스키마

**입력**(프롬프트): 앵커 후보 목록(`id·name·type·dist·sector`) + 시작 + target + prefs.
**출력**(tool): **앵커 id 순서 + 루프 방향** — 좌표·이름 발명 **불가**(스키마에서 제거).

```
build_running_loop(
  anchor_ids: [int],          # 방문 순서 (후보 목록의 id만)
  loop_direction: "cw"|"ccw", # 각도 진행 방향
  pitstop_anchor_id: int|null # 선택적 목적지(dead-end 허용)
)
```
- **좌표 발명 원천 차단** → §8.14(제한구역)·무명 지점·지명 hallucination **구조적 소거**
  (앵커는 전부 vetted 실재 공공 지점).
- **9-풀 접합**: 풀 유지하되 **다양성 축을 좌표→앵커 선택**으로 전환. 각 롤 = 다른
  앵커 부분집합·순서·방향 → 기하 → 스냅. 스태거(0.25s)·시간예산(20s)·leg 상한(40)·
  밴드 게이트(`_within_band` [target−0.3,+0.5]) **전부 불변 재사용**.
- **【제안】 Gemini 콜 축소 여지**: 앵커 순서는 서버가 각도 정렬로 결정론 생성 가능 →
  Gemini를 1콜(테마·강조 앵커 선택)로 줄이거나 완전 생략도 옵션. Phase 0에선 "Gemini
  소역할 유지(어느 앵커가 좋은 러닝인지 판단) + 서버 기하"를 기본안, 콜 절감은 슬라이스
  5에서 A/B로 결정.

## 3. 기하 계산 — 원형성 구조적 보장 (에픽의 존재 이유)

### 3.1 각도 분산 루프
- 앵커를 **시작 기준 방위각으로 정렬**(polar sort). 서로 다른 sector의 앵커를 각도
  순서로 방문 → **각 leg이 각도를 전진** → **되돌기(out-and-back)가 구조적으로 불가**.
- 대비: 현행은 Gemini가 좌표를 아무렇게나 찍어 T-map이 왕복으로 스냅(retrace 제어 불가).
  **앵커 각도 정렬은 서버가 순서를 통제**하므로 **원형을 보장**할 수 있다 — 이게 선택·
  프롬프트 층이 못 하던 것(§8.13·8.15).
- 구현: 시작 인근 앵커 3~5개를 **서로 다른 sector**에서 선택 → 각도 순 방문 → 시작 복귀.
  볼록껍질(convex-hull) 유사 순회로 자기교차·스퍼 최소화.

### 3.2 T-map 앵커 체인 루프
- 순서 확정된 앵커로 leg-by-leg 스냅(**기존 `get_pedestrian_route` 재사용**).
  polyline·거리 산출은 현행과 동일 경로.

### 3.3 거리 수선 (Phase 1 #5 흡수)
- 스냅 결과가 **짧으면 "앵커 밀기"**: 가까운 앵커를 밴드 내 더 먼 앵커로 교체 / 복귀
  leg에 앵커 1개 추가. **길면**: 먼 앵커를 가까운 것으로 교체 / 앵커 수 축소.
- **격자 ratio 재사용**: 초기 앵커 반경 조준에 `_GRID_RATIOS`(뚝섬1.84·성수1.62·
  여의도1.58·청라1.85·목동1.41·강남1.38·default 1.6) 활용 — 앵커를 어느 거리대에서
  고를지 시드. 좌표 발명 없이 **앵커 거리 선택으로 거리 제어**(체인 타깃 추측 대체).
- 밴드 게이트는 불변 — 수선 후에도 밴드 내 최적을 선택.

## 4. 마이그레이션 전략

### 4.1 프론트 계약 불변 (검증)
- 응답은 여전히 `RouteResponse`(summary·waypoints[]·polyline·total_distance_km·
  is_one_way·target_missed·search_radius_km…). **앵커 = 중립 라벨 waypoint**(현행 라벨
  스키마 그대로), pitstop은 기존 Kakao 해석. **shape·필드 전부 불변 → 프론트 변경 0.**
- `waypoints[].coordinate`가 실재 앵커라 역지오코딩 표시명도 더 정확해짐(부수 이득).

### 4.2 신구 병행
- **엔진 플래그**: `gen_meta.engine = "anchor"|"pool_v87"`. 확률적 롤아웃(예: anchor
  X% / v87 (100−X)%) 또는 격자별(앵커 풍부 지역부터).
- **라이브 A/B**: gen_meta에 engine·retrace·park·verdict 이미 기록 → **베타 트래픽으로
  두 엔진 실측 비교**(별도 측정 불요, §8.15 방식의 상시화).
- **롤백 단위**: 앵커 경로는 플래그 뒤 **독립 분기** — X=0으로 즉시 현행 복귀.

## 6. 검증 계획

- **§E 다좌표**: 청라·성수·강남·목동·신사·**용산**(부검 3좌표 포함) × 5 × [anchor vs v87]
  = 60생성, 실 파이프라인. gen_meta engine 태그로 비교.
- **지표**: retrace·zigzag·park·거리 밴드 적중률·서빙률 + **apt_signal**(제한구역 신호).
- **합격선 (오너 확정 2026-07-23, 재프레임 후 — 카운트 retrace 폐기, 체감 회랑으로 교체. §8.16)**:
  가치 명제 = **장거리 왕복 스퍼 반감 + 접근-안전 + 실공원 품질**.
  | 지표 | 현행 v87 | **앵커 성공선** |
  |---|---|---|
  | **longest_retrace_m 중앙** | 1106 | **≤ 600 & v87比 ≥40%↓** (최악 스퍼 반감) |
  | 거리 밴드 적중률 | 93 | ≥ 90 |
  | park 중앙값 | 0.67 | ≥ 0.8 |
  | 서빙률 | 15/15 | 동등 |
  | long_spur_count 중앙 | 2.5 | **v87 초과 금지** |
  | apt_signal(제한구역) | 관측중 | **~0**(앵커 vetted 공공) |
  - **폐기**: retrace 카운트 ≤30 — 마이크로 반전 과다 집계로 체감과 어긋남(§8.16).
  - **핵심 = longest_retrace_m 반감**(장거리 왕복 소거). 이게 원형성 약속의 체감 생존분.

## 7. 구현 슬라이스 + 착수 타이밍

### 7.1 슬라이스 (각 오프라인 테스트 가능, 독립 롤백)
1. **앵커 검색 층**: Kakao 다키워드 + `rank_places_for_keyword` 재사용 + sector 계산 +
   격자 캐시. dead-end 프로브. → 순수 함수/오프라인 테스트.
2. **앵커→기하**: 각도 정렬 루프 + T-map 스냅 + 거리 수선. → 오프라인(실 T-map) 테스트.
3. **Gemini 축소 스키마**: 앵커 선택 tool + 프롬프트. 또는 서버 결정론 순서(콜 절감안).
4. **파이프라인 통합**: 플래그 뒤 접합 + gen_meta engine 태그 + 폴백 배선.
5. **롤아웃**: 확률적 X% + 라이브 A/B 관측 + 합격선 게이트 + 단계 상향.

### 7.2 착수 타이밍 권고 (오너 결정 재료)
- **외부 게이트(베타/출시) 前 착수**: 출시부터 깔끔한 코스(첫인상↑). 단 **베타 지연**,
  앵커 미검증분 리스크.
- **後 착수(권고)**: **베타는 현행 v87로 출시**(서빙 93%·검증됨) → 앵커는 **베타 개시
  후 플래그 뒤 점진 롤아웃 + 라이브 A/B**(슬라이스 5). 품질 개선을 **출시 타이밍과
  분리**해 디리스크, 실트래픽으로 합격선 검증.
- **【권고】 슬라이스 1~4를 지금 설계·오프라인 구현**(프로덕션 무영향) → **베타 v87 출시**
  → **베타 후 슬라이스 5 롤아웃**. 세 부검이 앵커 필요성을 확정했으나 **베타를 막을
  이유는 아님**(현행이 서빙은 함) — 병행이 최적.

## 8. 미해결·Phase 1 이관

- dead-end 프로브의 정확한 휴리스틱(양방향 프로브 vs 주소 신호) — 슬라이스 1에서 실측 결정.
- Gemini 콜 수(9-풀 유지 vs 서버 결정론 vs 1콜) — 슬라이스 3/5 A/B로 결정.
- 앵커 캐시 무효화 정책(신규 공원 개장 등) — TTL vs 이벤트.
- 각도 분산이 앵커 빈곤 지역에서 무너질 때의 최소 sector 수 — 슬라이스 2 실측.

## 9. 동결 상태 + 부활 형태 (오너 확정 2026-07-23)

**동결**: 슬라이스 1~3 오프라인 완결, 프로덕션 미배선. 규칙 기반 도달점 = longest
802(v87 1106比 27%↓)·hit 83%·park 1.0·서빙 18/18·접근-안전 해결. §6 ①②⑤ 미달.

**부활 시 통합 형태 (지정)**: **풀 엔진 교체 아님 → 혼합 풀 기여자.**
- 기존 9-풀에 **앵커 롤 2~3개**만 추가(나머지 6~7롤은 v87 좌표 발명 유지).
- **v87 롤이 거리 보장**(hit 93% 유지), **앵커 롤이 park·spur tiebreak 경쟁**
  (spur-first + park). 밴드 게이트·선택 층 불변.
