# 감사 / 버그 사냥

우리는 이 방식으로 24건을 발견·전량 처리했다(`docs/AUDIT_BACKLOG.md`).
핵심은 **분류별 전수 스윕 + 재현 + read-only 원칙**이다.

## 원칙

- **감사 중 코드 수정 금지(read-only)** — 먼저 전량을 발견·기록한다. 수정은
  발견을 다 모은 뒤 배치로. 스윕 중 고치면 커버리지가 무너진다.
- **재현 먼저** — 버그 리포트는 최신 main + 서버 재시작 후 재현 시도. 재현
  불가면 "리포터 측 구코드 가능성"으로 결론(실사례 3건). uvicorn은 pull로 코드가
  안 바뀌므로 "서버 구코드"를 항상 의심.
- **추측 금지** — 성능은 계측 먼저(범인이 T-map 아닌 Gemini thinking이었음),
  스키마는 실조회 먼저.

## 서식지 7분류 (이 순서로 스윕)

1. **레이스**: check-then-act 창(count→check→act). 앱 트랜잭션이 없어 unique로
   못 막는 "개수/집계 조건"이 핵심 타깃(정원·생성한도·주간쿼터·RSVP 마감창).
   → 원자화는 `freshrun-sql` / `docs/RACE_FIX_DESIGN.md`.
2. **권한**: 소유권·멤버십 검사 누락. 차단은 **404 은닉**이 표준(403 아님).
3. **프라이버시**: 응답에 비공개 필드/값 누출. visibility 매트릭스 전수.
4. **비용**: Gemini/외부 API 과호출·중복 호출(쿼터 우회 시 유료 반복).
5. **정합성**: FK cascade·삭제 시 잔여(알림·집계), 탈퇴자 표 포함 여부.
6. **입력**: max_length·limit 클램프·int 상한·datetime tz 필수(naive 거부)·
   distance `ge` 하한(1e-308→0.00 방지).
7. **커버리지**: 인증 누락 엔드포인트, 경로 순서(고정 vs 패턴), 테스트 공백.

## 재현 조건

- **레이스**: mock 순차 패치는 DB 원자성에 무효. `asyncio.gather` 실동시 발사 +
  **불변식 assert**(정원 초과 0건, free 소유 1건, 주간 count==limit). 옛 버그
  재현은 창이 좁아 K를 크게(10~20 동시)하거나 선택; **불변식 검증이 본질**.
- **프라이버시**: 응답에 키 부재 **+** 값 문자열이 응답 전체에 부재(이중).

## 심각도 기준

- **높음(H)**: 정책 위반이 실사용자에게 발생(데이터 누출·권한 우회·정원 초과 상시).
- **중간(M)**: 조건부/저빈도(레이스·소액 비용·입력 검증 구멍).
- **낮음(L)**: 방어적 개선·μs급 엣지·문서/드리프트(예: RSVP 마감 μs 창).

## 보고 양식

발견마다: **[심각도] 제목 · 위치(file:line) · 재현 조건 · 영향 · 수정안.**
심각도별로 묶어 목록화(H → M → L). 재현 불가 항목은 "검증 불가"로 표기.

## 발견 → 배치 수정

스윕 완료 후 심각도·주제로 묶어 **배치 커밋**(실사례: 배치1 sanity, 배치2 입력
검증, 배치3 소품, 배치4 L-소품, 배치5 레이스 묶음). 각 배치는 완료의 정의
(테스트+회귀+SQL 페어+보고)를 따른다 — `../../CLAUDE.md`.

## 히스토리 시크릿 스캔 (정기·출시 전 필수)

**왜 별도인가**: CLAUDE.md §A5의 pre-commit 검사는 `git grep --cached`라 **스테이지만**
본다 — 이미 커밋된 히스토리에 잠복한 시크릿은 절대 못 잡는다. 실사례: service_role 키가
초기 커밋(`e9161a7` 테스트 파일)에 하드코딩됐다가 후속 커밋에서 제거됐으나 **히스토리에
잔존**, 7월 노출을 pre-commit 검사가 놓치고 8월 보안 감사에서야 발견(회전은 2026-07-08
선행 완료라 무피해로 마감).

**전수 스캔 커맨드**(값 노출 금지 — 마스킹 필수):
```
git log --all -p \
  | grep -E "sb_(secret|publishable)_|eyJ[A-Za-z0-9_-]{30,}|service_role|sk-[A-Za-z0-9]{16,}|AIza" \
  | sed -E 's/(.{40}).*/\1.../'
```
- 패턴: `sb_secret_`·`sb_publishable_`(Supabase 신규 키) · `eyJ`(JWT — 레거시 anon/
  service_role) · `service_role` · `sk-`(OpenAI) · `AIza`(Google).
- **매치 위치 특정**: `git log --all --oneline -S "<리터럴>"` 로 유입 커밋 추적.
- `.env.example` placeholder(`your-...`·`sk-...` 주석)는 오탐 — 실값 형태만 조사.

**발견 시 순서**: ① 노출 키 **생존 판정**(Supabase/제공자 콘솔에서 회전 이력 확인 —
살아있으면 **즉시 회전**, 죽었으면 위생 문제로 강등) ② **회전이 실 remediation**(히스토리·
클론·GitHub 캐시에 이미 퍼졌을 수 있어 영구 침해 간주) ③ 히스토리 스크럽은 방어심화 —
`docs/SECRET_SCRUB.md` 절차(filter-repo, 클론 재동기화, 캐시 purge). **filter-repo 실행은
히스토리 재작성이라 오너 명시 승인 필수**(되돌리기 어려움).
